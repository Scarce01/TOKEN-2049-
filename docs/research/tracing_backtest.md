# 溯源回测：方法、三个案例、坏结果

状态：2026-10-06，最终运行。代码在 `analysis/trace_bybit/`（名字沿用，现在支持多个案例）。每个数字都是公开链上数据（`[on-chain]`），除非另有标注。

## 1. 要回答的问题

诱饵被碰时，我们手上只有**一个**攻击者地址。从这一个地址出发，只用公开链上数据，能多快、多准地找到攻击者控制的其他钱包？标准答案用独立机构事后公布的地址名单。

## 2. 方法

| 步骤 | 做法 | 为什么 |
| --- | --- | --- |
| 数据 | Etherscan V2（按地址抓 ETH、内部转账、白名单代币）；兑换交易另用公共 RPC 读回执 | 只用公开数据；全部缓存，评分阶段完全离线 |
| 污点模型 | 按时间顺序重放，按比例分配（haircut）：地址转出 v 时，带走 v × 被污染流入 ÷ 总流入 | 只有收到赃款之后的转出才算 |
| 兑换感知 | 同一笔交易、或同一对手方换回来的资金，仍算原地址的赃款，不算一跳 | Bybit：stETH 换成 ETH 后，最初的版本就追丢了 |
| 兑换给新钱包 | 同一笔交易里，钱进了 DEX、DEX 付给另一个地址，那个地址被污染（交易所、桥、服务除外） | UniswapX、聚合器 |
| 断点 | 交易所标签、已验证合约（按合约名分类）、50 个以上不同转入方的地址（服务）、零地址（销毁） | 追到这里就交给专业公司 |
| EIP-7702 | 委托代码（`0xef0100` + 地址）**不算合约** | Bitget Exploiter 2 就是委托钱包；不处理就会在攻击者自己的钱包停下 |
| 定向深追 | 最多 4 跳；只继续追污点 ≥ 50% 的地址；每层最多抓 250 个（按污染金额） | 控制抓取量 |
| 评分（主指标） | 候选：4 跳内、不是断点、污点 ≥ 10%；**按污染金额排序** | 值班人员先看「拿了最多赃款」的地址 |
| 整数运算 | 金额用 wei 或 micro-USD 整数，比例用 ppm；核心代码有「不准用浮点」的测试 | 将来放进 CRE 要能共识 |
| 跨币种 | 多资产案例按固定价格折成 micro-USD；ETH/USD 取 Chainlink 喂价在起始区块的值（两个 RPC 读数一致），稳定币按 1 美元（假设值） | Bitget、Stake 主要是稳定币 |

## 3. 结果

### 汇总（最终运行，2026-10-06）

| 案例 | 种子（1 个） | 标准答案 | 找到 | 按污染金额排序，前 N 名命中 | 首次触及时间（攻击后） |
| --- | --- | --- | --- | --- | --- |
| **Bybit**（2025-02） | `0x47666`：受害冷钱包唯一的收款方 | FBI PSA I-022625-PSA，51 个 | **51/51**（1 跳 41、2 跳 42、3 跳 51） | 前 51 名 49 个；前 102 名 51 个 | 最早 16 分钟，中位数 97 分钟；FBI 5 天后公布 |
| **Stake.com**（2023-09） | `0x3130…`：链上核实，收到 6,001 ETH + 590 万美元稳定币，与报道的损失一致 | FBI 公布的地址中，在以太坊上发过交易的 4 个（FBI 原文：以太坊 4、BSC 5、Polygon 2） | **4/4**，2 跳 | 前 8 名 4 个 | 最早 14 分钟，中位数约 26 分钟；FBI 约 2 天后公布 |
| **Bitget**（2026-09） | `0x770b`（Exploiter 1，6 个来源） | 14 个至少 2 个来源核实的攻击者地址（Bitquery + Etherscan 标签） | **8/14**（57%） | 前 14 名 8 个（找到的全部排在最前） | 最早 34 分钟 |

每个案例离线评分重算一次，输出逐字节相同（sha256 一致）。

### 每项改进的作用

| 改进 | 证据 |
| --- | --- |
| 兑换感知 | 中期快照（只抓了 530 个地址）：V1 40/51 → V2 51/51。最终完整数据（1,256 个地址）：V1 50/51 → V2 51/51，前 100 名 50 → 51。**结论：数据有限时它决定往哪追，数据完整时增益小** |
| EIP-7702 修复 | Bitget 2/14 → 7/14（比例门槛 50%） |
| 按金额排序（比例只做 10% 下限） | Bitget 6/14 → 8/14 |
| 粉尘不算「服务」的转入方 | Bybit 44/51 → 51/51（修复前，7 个攻击者钱包因收到大量粉尘被误判成交易所） |
| 兑换给新钱包（交易所级展开，每层最多 100 笔） | 没有带来可测的提升；上限 400 与 100 的结果相同 |

| 模型（同一份最终 Bybit 数据，3 跳） | 找到 | 标记的地址数 |
| --- | --- | --- |
| V0 朴素广度搜索（没有金额，无法排序） | 51/51 | 2,974 |
| V1 按比例分配 | 50/51 | 3,162 |
| V2 按比例 + 兑换感知 + 服务识别 | 51/51 | 3,239 |

标记数量都很大，所以主指标用「按金额排序的前 N 名」，不用整体精确率。

### 确定性与交叉核对

- 每个案例离线评分跑两次，输出 sha256 相同。
- Bybit 攻击路径上 3 个关键地址的 **269 条边**，用两个独立公共 RPC（publicnode、dRPC）逐字段核对：**0 处不符**。13 笔合约内部转账，公共 RPC 不提供追踪接口，无法核对。
- 单元测试 30 个（手算的混合污点、时间顺序、环、打乱输入顺序不变、兑换、兑换给新钱包、交易所不算兑换、EIP-7702、断点不算标记、粉尘不算服务、核心代码不用浮点）。

## 4. 坏结果与限制（台上主动说）

| # | 坏结果 | 原因 | 处理 |
| --- | --- | --- | --- |
| 1 | **Bitget 只找到 8/14** | 剩下的 6 个，资金经 **Stargate、Across 跨链**进入以太坊（Exploiter 7、8、21 已核实），或来自没追到的上游 | 跨链追踪要配对两条链的桥存取；免费的 Etherscan key 只覆盖以太坊、Arbitrum、Polygon，Base、Optimism、BSC、Avalanche 要付费。**这是产品边界：跨链之后交给专业公司** |
| 2 | **Bybit 是容易的案例** | 攻击者从一个地址按整数拆分，FBI 名单大部分就是这批钱包；3 跳以外经 THORChain、eXch 换成 BTC 的部分没测 | 用 Stake、Bitget 补充；Bitget 证明了难度 |
| 3 | **标准答案的性质不同** | Bybit、Stake 用 FBI 名单（官方调查）；Bitget 用分析师标签，方法和我们同类 | Bitget 结果说服力较弱，要分开讲 |
| 4 | **精确率只是下界** | 名单不完整。例：Bybit 的 `0x36ed…`、`0x4571…` 和 Stake 的 3 个钱包，污点 100%、形态与攻击者钱包相同，但不在名单上 | 用「前 N 名命中」代替整体精确率 |
| 5 | **时间优势要打折** | 社区（ZachXBT、Arkham、项目方自己）通常当天就公开地址；FBI 是官方名单的时间 | 只说「比官方名单早」 |
| 6 | **只追白名单资产** | Bybit：ETH、WETH、stETH、mETH、cmETH（1:1 折算）；Bitget、Stake：ETH、WETH、USDT、USDC、DAI | 其他代币不追，也顺带挡掉假代币投毒 |
| 7 | **合约判断用最新状态** | Etherscan 不提供历史状态 | 窗口之后自毁的合约会漏判（少见）；RPC 出错直接报错，不再默认为「不是合约」 |
| 8 | **单一主数据源** | Etherscan；RPC 只做交叉核对和兑换展开 | 已核对的部分 0 不符 |
| 9 | **我中途修过的 bug** | 历史状态报错被当成「不是合约」（断点全部失效）；零地址被当嫌疑地址；断点被算进标记；EIP-7702 委托钱包被当合约；攻击者钱包收到大量粉尘被当成交易所 | 都已修复，并各自有测试；每次都是对比结果与预期不符时发现的 |
| 10 | **交易级展开有上限** | 每层最多展开 100 笔兑换交易（按金额从大到小） | 为了在免费 API 限速下跑完；Bitget、Stake 在 400 与 100 下结果相同 |

## 5. 对 pitch 的说法

> 「诱饵被碰时，我们手上只有一个地址。在三个真实案例上，只用公开链上数据：Bybit 3 跳内找到 FBI 名单全部 51 个，而官方名单 5 天后才公布；Stake 的 FBI 以太坊地址 4 个全部找到，最快 14 分钟。跨链之后的部分，例如 Bitget 经 Stargate 和 Across 转移的资金（我们找到 8/14），交给 Chainalysis、TRM 这类追踪公司，我们是他们的上游。」

## 6. 怎么重跑

```bash
cd analysis/trace_bybit
echo "ETHERSCAN_API_KEY=..." > .env          # 不进 git
python3 -m pytest -q                         # 30 个单元测试
python3 run.py fetch --case stake            # 联网，写缓存 analysis/out/trace_stake/cache
python3 run.py score --case stake            # 离线，写 results/stake_result_A.json
python3 run.py fetch --seeds A && python3 run.py score --seeds A   # Bybit
python3 bench.py --seeds A                   # V0 / V1 / V2 对比（只用缓存）
python3 verify_rpc.py <address> ...          # 与公共 RPC 逐边核对
```
