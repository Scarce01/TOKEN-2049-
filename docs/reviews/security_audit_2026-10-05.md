# Quorum 全量安全审查（branch v0，2026-10-05）

范围：contracts/src（含 lib）、contracts/script/Deploy.s.sol、workflows（trap、cosign、patrol、common）、packages/shared/src（ids、eip712、report、seal、merkle）、apps/exchange-api/src、apps/console/app/api 与 lib/server.ts、services/decoy-admin、supabase/migrations。威胁模型按 .claude/agents/web3-auditor.md：交易所后台、数据库、admin 路由全部失守；攻击者可调用任何公开函数、抢跑、重放、刷量。

## 已检查、未发现问题

- 资金路径：`QuorumVault.execute` 每次都经 `consumeVerdict`，要么是未用、未释放、未过期且 userIdHash 相符的 APPROVE，要么是两位人员加 MANUAL_DELAY 的 `manualOf`；txHash 含 chainId 与金库地址，裁决不能跨金库使用；`paid[userIdHash][nonce]` 在外部调用前写入；SWEEP 只到冷钱包，TOPUP 只能温到热。
- OfficerAuth：digest 绑定 verifyingContract（各合约各自的 domain），CANCEL_QUEUED 签名不能跨合约重用；签名人严格升序，同一人不能算两次；每个 digest 只能用一次。
- onReport：PROD 解析 metadata 的 name / owner 偏移正确；SIM 用 tx.origin（已知弱点，代码注释有说明）；过期报告只放行收紧类；SCORE / VERDICT 顺序检查与 `_scoreConflict` 在每次 onReport 前后清零，自调用之间正确传递。
- VERDICT：只写一次；APPROVE 降级条件（signer == keyOf、approvedOf + amount ≤ depositedOf）在合约端复核；`releaseExpired` 只释放未用且已过期的 APPROVE，边界与 `consumeVerdict` 一致。
- Cosign 关 1 到 3 重算 txHash、逐字段比对 intent 与 request、signer 来自链上 ecrecover，不信任后台提交的字段；所有读取钉在事件区块；未见 Date.now、Math.random、浮点金额、node:crypto、fetch。
- Console 服务端路由：都先 `requireOfficer`（Supabase getUser + app_metadata.role），SQL 全部是参数化模板；SET ROLE authenticated 只用常量字符串。
- exchange-api 与 exchange_* schema 中没有判断逻辑或诱饵清单；traps 只有 quorum_svc、trap_sync_svc、console_svc 与 RLS 下的人员可读。
