# Quorum: results so far (2026-10-05)

Exported from README.md at main c0dfdd8.


Source types: **on-chain** = public on-chain data (BigQuery `crypto_ethereum`, Etherscan), **assumed** = simulation
or assumed parameters, **test** = automated test result. No testnet-measured numbers yet (needs deployment).
Details and queries: [docs/STATUS.md](docs/STATUS.md), `datasets/public/`, `analysis/`.

## Bad

| Result | Number | Source | Why |
| --- | --- | --- | --- |
| **CUSUM misses the Bitget drain** | no alarm after the hack at any threshold h | on-chain | Design limit: per-minute log scale gives the biggest theft minute only z about 1.7; a few huge transfers spread over 2.5 hours never accumulate |
| CUSUM false alarms in normal times | 1.9 per day at h = 5; 0.27 per day at h = 12 | on-chain | target is under 1 per month, so h must be high, which makes it less sensitive |
| **Quota bucket only helps in the first minutes** | by 19:05: fast-lane bound USD 16.9M vs USD 47.6M stolen; ETH bound 2,435 vs 7,131 stolen | on-chain | Bitget's scale is large; an attacker who splits transfers is slowed, not stopped |
| **Decoys still distinguishable** (D28 fails) | top-60 accounts: AUC 0.71 / 0.58, upper bound 0.88, target <= 0.65 | assumed | only 10 decoys (wide interval); the generator may leak through activity features |
| "Hugging the fake threshold" lambda set too low | real users do it 0.004% to 0.03% of the time vs 0.5% assumed | on-chain | real data implies lambda about 7,560 (one signal alone reaches L3) |
| Synthetic false-pending rate too high | A 5.8%, B 12.0% | assumed | synthetic model has no re-deposits; superseded by the 0.14% on real data, not to be quoted |
| **Invariants do not cover the legitimate path** | test audit: removing the freeze check, quota deduction or paid check from the vault still passes I1 and I6; I2 (verdict immutable) cannot fail because no handler re-sends a verdict. Only unit tests catch these | test | handlers only drive attacker calls; ghost-variable checks on execute, sweep, topUp, fund still to add |
| No-backdoor invariant (I7) flaky | fails at 256 fuzz runs (fuzzer can pick the timelock as caller); passes at the default 64 | test | handler must exclude the timelock; fix pending |
| "Careful" attacker figure withdrawn | previously reported 99%; the model only drops 30% of candidates at random and cannot avoid decoys by design | assumed | strategy must use the D28 features (for example nonce = 0) before any number is quoted |
| Gate 7 number not reproducible yet | the SQL behind 14 per 10,000 is not committed; caps are scaled from per-minute p99 flow, and the over-USD-1M tail still includes Binance internal transfers | on-chain | commit the query, scale from single-withdrawal sizes, exclude known Binance wallets, add a sensitivity table |
| Key change can be hijacked (audit High 3) | `requestKeyChange` needs only the new key's signature | test | design change; open decision in STATUS (43 F3, three-tier key registration) |
| Tracing ground truth incomplete | only 3 of 7 Bybit seed addresses are in the FBI list | on-chain | recall against the FBI list undercounts the first hop |

Framing notes: Bitget's 18:31 test transfer came from a real hot wallet, not a decoy (say "if the attacker first probes a
decoy, tightening happens at that moment"). The "USD 228M in 18 minutes" figure is Arkham's, not BlockSec's.
Real withdrawal data covers Binance only (the other labelled exchange addresses were idle that month).

Open decisions for the team (magnitude rule next to CUSUM, C multiplier, threshold-hug lambda, D28 evaluation,
tracing ground truth) are in [docs/STATUS.md](docs/STATUS.md) under "待决定".
