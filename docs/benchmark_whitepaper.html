1What we measured

Qu3ee plants decoys inside an exchange. When an attacker touches one, Chainlink CRE nodes tighten withdrawals on chain and the attacker's address is shared with other exchanges. This report covers what happens next: can we follow the money from that one address, how fast, and does the alarm fire before the exchange's own monitoring?

Every case starts from one seed address and uses only public chain data. Answers are scored against an outside list the method never sees.

2Tracing back from one address

Taint spreads in time order with the haircut rule: a wallet that receives stolen and clean money passes on the stolen share in proportion. The tracer understands swaps (a DEX trade that pays a fresh wallet), stops at exchanges, bridges and contracts, and only follows wallets that are at least 50% tainted. All amounts are integers, so every run gives the same bytes.

3Following money across bridges

On Bitget the Ethereum-only trace stopped at 8 of 14. The missing wallets were funded by theft on Arbitrum, Optimism, Base and BSC that the attacker bridged back to Ethereum. Those inflows looked clean, and they diluted the hub wallet below the 50% follow line, so its children were lost too.

Method

  • The same seed address is followed on every origin chain (attackers reuse one key across EVM chains), using plain JSON-RPC from NOWNodes.
  • Every transaction an address sent is found by bisecting its nonce (about 21 calls per transaction). Native transfers are visible without an indexer.
  • Bridge deposits are decoded from receipts: Across FundsDeposited, Stargate OFTSent.
  • A deposit only counts after its Ethereum fill is found by the same identifier: Across by origin chain and deposit id, Stargate by message guid. A fill paid to a pass-through contract (AcrossAdapter) follows to the wallet it pays in the same transaction.
  • Each matched fill becomes an edge with the Ethereum transaction and log index, the same shape the CRE verify-edge handler reads.

5Raising the alarm: CUSUM and the spike rule

Patrol watches each hot vault's outflow per minute with CUSUM, which catches a slow rise. On Bitget it never fired at any threshold: idle minutes inflate the baseline spread, so the 34.75M USDT minute scored only about 1.7 standard deviations, and eight transfers over 2.5 hours never added up. The spike rule (Shewhart) is its classic companion: one minute above a cap raises the alarm at once. The action stays soft (refill halved); raising the alert level still needs a second signal.

8Limits

  • Decoys can still be told apart (AUC 0.71, target 0.65 or lower). Only 10 decoys; the generator may leak through activity features.
  • The quota bucket slows a split drain, it does not stop it: by 19:05 the fast lane allows at most 16.9M against 47.6M taken.
  • Bridges are partly covered: Across and Stargate are decoded; intent solvers, CCTP and Mayan are not. Past those, tracing firms take over.
  • Bitget's truth set is analyst labels, weaker than the FBI lists used for Bybit and Stake.
  • Trek's replay classifies with hindsight; live it classifies as money arrives.
  • The DON figures are single runs: one Trap touch and one Cosign withdrawal. The other prevention cases (forged signature, caps, officer hold) ran on the local fork only.
  • Bitget's 18:31 test transfer came from a real hot wallet, not a decoy. Any "what if it hit a decoy" is a hypothetical replay.

9Deployment plan

None of the steps below changes a contract. The spike rule is a configuration change; cross-chain tracing in real time is new workflow and service code.

Done

  1. Merged: product name, spike rule, cross-chain tracing, this benchmark (PRs #2 to #5).
  2. Public Base Sepolia, mode A: contracts in PROD behind the KeystoneForwarder; Patrol, Trap and Cosign on the Chainlink DON (private registry, no mainnet gas); workflow owner set through the timelock; CRE secrets uploaded.
  3. Spike rule on: spikeMax set in the deployed Patrol config (1,000 qUSD on the test token).

Now

  1. Frontend on the public deployment. Sliced log reads and neutral org names are merged (PR #10); the RPC target, the deployment file, the indexer and the attack flow move next.
  2. More runs on the DON. Repeat Trap and Cosign for medians, and run the other 7 prevention cases on the public chain.
  3. AWS. Containers for exchange-api, indexer, trap-sync, keeper and notifier; CDK stack; Supabase Cloud migrations; alarms (docs/38_phase8_aws.md).

Next: cross-chain tracing in real time (about 3 to 4 days)

  1. Trek on several chains. In real time Trek scans each block, so nonce bisection is not needed. Plug the Across and Stargate decoders from bridges.py into Trek's live source.
  2. A bridge edge for CRE verify-edge. Read the origin receipt (deposit) and the destination receipt (fill), check the identifiers match, then write the derived threat. Two receipts per edge halve the batch to 6 edges per call. ThreatRegistry already keys entries by chain id, so the contract stays as it is.
  3. Native transfers. verify-edge rejects native transfers today because a receipt carries no value, yet most of the stolen funds on L2s moved as native ETH. Ask the Chainlink mentor whether the CRE EVM client can read a transaction's value by hash.
  4. A paid data source. Scanning five chains in real time is about two calls per block: Arbitrum alone is roughly 700,000 calls a day, far above the free 100,000 a month. Use a paid NOWNodes plan, own nodes or websocket feeds.
  5. Testnet demo. Across runs between Sepolia, Base Sepolia and Arbitrum Sepolia: a decoy hit on Base Sepolia, the attacker bridges to Sepolia, Trek follows, verify-edge checks both chains. No mainnet funds needed.

10Reproduce

Every result in sections 2 to 5 re-runs from the repo. With the cache package unzipped into analysis/out/, no API keys are needed and the outputs match byte for byte.

cd analysis/trace_bybit
python3 run.py score --seeds A            # Bybit
python3 run.py score --case stake         # Stake
python3 run.py score --case bitget        # Bitget, Ethereum only
python3 xchain.py --case bitget           # Bitget, cross-chain
python3 trek.py replay                    # Trek replay
python3 ../bitget_spike.py                # spike rule
cd ../.. && python3 analysis/don_bench/don_benchmark.py --workflows quorum-trap,quorum-patrol --trap-trigger-tx <tx>   # DON
